SECOM 반도체 공정 불량 예측

UCI SECOM 데이터(웨이퍼 1,567장, 센서 590개)로 불량 웨이퍼를 잡아내는 분류 모델을 만들어 봤습니다.
불량 비율이 6.6%밖에 안 돼서 정확도 대신 불량을 몇 개나 잡았는지(FAIL Recall)를 기준으로 모델을 비교했습니다.


한눈에 보는 결과

- 기본 설정의 Random Forest, XGBoost, LightGBM은 정확도 93%가 나왔지만 테스트 불량 21개 중 하나도 못 잡았음
  전부 PASS로 찍어도 93%가 나오는 데이터라 정확도는 의미 없는 지표였음
- 최종 모델은 XGBoost + 클래스 가중치(scale_pos_weight 14.1) + 분류 임계값 0.35
  임계값은 학습 데이터 교차검증으로만 정했고, 테스트셋에서 불량 21개 중 10개 검출, 오탐 27개 (F1 0.345)
- 교차검증 기준으로 기대할 수 있는 Recall은 0.34 정도. 테스트 결과(0.48)는 이번 분할이 잘 나온 쪽이라고 봄
- 두 부스팅 모델이 공통으로 중요하다고 본 센서는 59번, 103번. 59번은 불량 웨이퍼의 중앙값이 5.52로 정상(0.72)보다 확연히 높았음

교차검증(학습 데이터 5-fold x 3회) PR-AUC는 XGBoost 0.19 ± 0.06, LightGBM 0.17 ± 0.06입니다. 무작위로 찍으면 0.066이 나옵니다.


전처리하면서 신경 쓴 부분

처음에는 전체 데이터로 결측치를 채우고 나서 train/test를 나눴는데, 이러면 테스트 데이터 정보가 학습에 섞여 들어갑니다.
그래서 순서를 바꿔서 분할부터 하고 나머지는 전부 학습 데이터 기준으로만 계산했습니다.

- train/test 8:2 층화 분할을 가장 먼저 수행
- 결측률 80% 이상 센서 제거 (학습 데이터 기준)
- 남은 결측치는 학습 데이터 중앙값으로 채움
- 값이 하나뿐인 센서 제거 → 590개에서 466개로 줄어듦
- 스케일링과 SMOTE도 학습 데이터에만 적용
- 교차검증 때도 fold마다 위 전처리를 새로 학습시킴


해보면서 알게 된 것

- SMOTE로 불량 샘플을 늘려도 Random Forest는 여전히 불량을 하나도 못 잡았음. 데이터를 늘리는 것보다 손실에 가중치를 주는 쪽이 효과가 있었음
- 가중치만 줘서는 부족했고, 예측 확률을 보니 실제 불량의 평균 확률이 0.30 정도였음. 기본 임계값 0.5로는 거의 다 PASS로 분류되는 구조였음
- 처음에는 테스트셋 결과표를 보고 임계값을 0.3으로 골라서 불량 12개 검출이라는 숫자를 얻었음
  그런데 이건 테스트셋에 맞춘 값이라 다시 학습 데이터 교차검증으로만 임계값을 정했고, 0.35가 나왔음
  결과는 10개 검출로 줄었지만 오탐이 40개에서 27개로 줄었고, 이쪽이 실제로 믿을 수 있는 숫자
- 임계값을 낮출수록 잡는 불량은 늘지만 오탐도 같이 늘어남 (교차검증 기준, XGBoost)

| --- | --- | --- | --- |

| 0.20 | 0.55 | 0.12 | 0.20 |

한계와 다음에 할 것

- 테스트 불량이 21개뿐이라 하나만 더 맞혀도 Recall이 5%p 가까이 바뀜. fold별 PR-AUC도 0.07~0.29로 편차가 커서 아직 실사용 수준이라고 보긴 어려움
- 임계값을 F1 기준으로 골랐는데, 실제 공정이라면 불량 1개를 놓치는 비용과 재검사 비용을 알아야 제대로 정할 수 있음
- 센서 이름이 익명이라 59번 센서가 실제 어떤 공정 값인지는 해석할 수 없었음
- 다음에는 중요 센서만 골라 쓰는 모델, 하이퍼파라미터 탐색을 교차검증 안에서 해볼 예정


폴더 구성

- data : 원본 데이터 (secom.data, secom_labels.data)
- notebooks/01~07 : EDA와 모델별 노트북. 각각 따로 실행 가능
- notebooks/08.CV Threshold.ipynb : 교차검증으로 임계값을 다시 정하고 테스트셋 1회 평가
- notebooks/sensosr.ipynb : XGBoost, LightGBM 중요 센서 비교
- notebooks/step1.ipynb : 59번, 103번 센서 정상/불량 분포 비교
- notebooks/comparison code : 기본 모델과 튜닝 모델 비교 그래프
- 00.total.ipynb : 전체 모델 성능 비교표
- results : 모델별 테스트 예측 결과 (y_true, y_pred)


실행 환경

Python 3.12, scikit-learn 1.9, imbalanced-learn 0.14, XGBoost 3.3, LightGBM 4.6

pip install -r requirements.txt 후 노트북을 프로젝트 루트나 notebooks 폴더에서 실행하면 됩니다.
그래프 한글 폰트는 Windows 맑은 고딕 기준입니다.
